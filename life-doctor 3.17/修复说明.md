## 1. 病程稳定 45 秒不结算 → 已修

**现象**：把所有「必需处置」做完、生命体征也正常了，等 45 秒游戏没有任何反应。

**原因（三个）**：

1. **结算弹窗会被吞掉。** `main.js` 里死亡/成功弹窗用
   `setTimeout(() => { if (!UI.isModalOpen()) UI.openXxx(sim); }, 400)`。
   只要当时正开着任何弹窗（用药面板、处理指南、体格检查……），结算就被静默丢弃；
   而 `sim.dead` 已经置真、主循环不再推进 —— 表现就是「界面卡住，没有结算」。
   → 改为 `openEndModal()`：先关掉检索与当前弹窗，再无条件弹出结算。
2. **有 4 个病例没有任何 `need: true` 的处置项**（弥散性血管内凝血、急性一氧化碳中毒、
   重症中暑/热射病、苯二氮䓬类中毒），`checkTreat()` 的 `needAny` 永远为假，
   `d.controlled` 永远不会置真 → 这些病例**在数学上不可能通关**。
   → 引擎新增「支持治疗型病例」通道：没有必需项时，完成**任意一项**对症处置 +
   体征达标即可结算；疾病面板同时改成「对症支持 · 已完成 N 项」并给出说明。
3. **稳定性判定太宽松、计时语义不对。** 原来是「控制后满 45 秒**且此刻**稳定」，
   只要某一瞬间达标就直接判成功；而稳定条件只看 MAP / SpO₂ / 乳酸 / 脉搏，
   体温 41℃、血钾 9 的濒死病人也算「稳定」。
   → 改为**连续稳定 45 秒**（允许 2.5 秒抖动不清零），并补齐判定项：
   MAP > 60、SpO₂ > 88%、乳酸 < 3.2、体温 34.5–39.2℃、血钾 3.0–6.0、Hb > 6、有脉搏。
   疾病面板新增「稳定计时 xx/45s」进度条，玩家能看见倒计时，不会再以为卡死。

## 2. 没有死亡模拟 → 已修

- 死亡流程本身（无脉 4 分钟 → 死亡记录 → 签署 → 死亡证明）是通的，
  但同样会被上面第 1 条的「弹窗占用」吞掉；另外**疾病偏移量算错**把病人变成了血压 300、
  体温 43℃ 的怪物，4 分钟窗口根本走不到。
- 现在：无脉立即亮起顶部红色抢救条与倒计时；倒计时归零 → 死亡记录（含直接死因、
  抢救时长、关键处置完成度、签署医师）→ 签署后生成死亡证明。全程强制弹出，不会被其它弹窗挡住。
- 补了两处会导致「永远死不掉」的数据漏洞：`急性阑尾炎`、`急性胆囊炎` 的致死期没有设置心律，
  已补 `asystole`。
- 新增「可逆停搏」：病因纠正（血钾 < 6、氧合恢复、体温 > 33℃）后持续 CPR 有 ROSC 机会，
  不再出现「除颤/按压按到死也回不来」的死局。

## 3. 5000 氯化钾静推不死 → 已修

**原因**：药效用的是 Hill 饱和方程（`Emax·C^h/(EC50^h+C^h)`，EC50 = 1 个常用剂量），
氯化钾对血钾的最大效应只有 +0.7（毒性再 +1.5），无论输入 20 mEq 还是 5000 mEq，
血钾都被锁死在 6.4 左右；而触发室颤的门槛是 7.2 → 永远死不了。
另外「静推」途径根本没开放（`routes: ["iv_inf","po"]`）。

**改法**：

- `effectOf()` 新增 `linear: true` 的**剂量负荷型**效应，按剂量倍数线性累加，不再饱和；
  氯化钾的血钾效应改用线性（常规 20 mEq ≈ +0.45，大剂量线性冲顶）。
- 重写高钾血症级联：> 5.5 心肌易激 → > 6.5 传导抑制/QRS 增宽/心率与收缩力下降 →
  > 7.0 随时室颤 → > 8.0 随时停搏 → **≥ 10 心电直线**（心肌电静息）。
- 氯化钾开放「静推」途径用于教学，执行时弹出绝对禁忌警告；
  血钾 ≥ 11 时抢救窗口从 4 分钟缩短到 **8 秒**，随后直接宣告死亡（死因写明血清钾数值）。
- 实测：静推 5000 mEq → 2 秒内心电直线，8 秒后死亡；常规 20 mEq/h 滴注血钾 4.6，无症状。

## 4. 顺带修掉的底层 bug（影响全局手感）

- **`applyMods()` 把健康基线当累加器初值**：疾病/药物只要碰一个此前没被写过的指标，
  就会写入 `健康值 + 偏移`，再叠到基线上 → 相当于同一项被加了两次。
  实测「一氧化碳中毒」到院心率 178、收缩压 300、体温 43℃。已改为纯增量累加。
- **`v.map` 在脉搏判定之后才计算**：`hasPulse()` 读到的永远是上一次的 MAP（健康值 89），
  所以收缩压 0 的病人也被判「有脉搏」。已调整为先算 MAP 再判脉搏。
- **初诊体征被重复叠加**：`vitals` 与 `stages[0].changes` 同一项都写时会加两遍
  （脓毒性休克收缩压被压到 18）。现在第 0 期只补齐 `vitals` 没覆盖的项。
- **血压偏移同时写 `sbp` 和 `map`**：12 个病例两处都给，MAP 又按 1.25 折算进收缩压，
  等于三倍叠加。现在有 `sbp` 时忽略 `map`（MAP 由收缩压/舒张压推导）。
- **数据笔误**：急性尿潴留 `k: 5.2`（到院血钾 9.4）→ 改为 0.9。

# 第五轮：处方区「乱闪」修复（2026-10-24 深夜）

## 18. 现象
点开右侧「处方」标签后整个列表不停闪动，条目像是重新出现；鼠标悬停/点「停止」时也会跳。

## 19. 根因
`UI.renderRx()` 每 180 ms 被主循环调用一次，而它**每次都直接重写 `#rxBody` 的 innerHTML**：
```js
if (list.length === lastRxN) { /* 更新滴注剩余状态 */ }   // ← 空分支，什么都没做
body.innerHTML = arr.map(...).join('');                    // ← 每帧重建全部节点
```
而 `.rx-item` 的 CSS 带 `animation: slidein .3s`，DOM 每次重建都会把所有条目的入场动画重播一遍，
于是整块区域就像在闪；同时「起效中 Ns」的秒数每秒都在变，进一步保证每帧都不同。

## 20. 修法
- **结构指纹**：把每条医嘱的 `uid + 过敏失败 / 滴注中 / 已停止 / 已代谢 / 过量` 拼成签名，
  签名不变就**完全不碰 DOM**。
- **只改文字**：状态文字（起效中 / 作用中 / 已代谢 / 未起效）单独放在 `<b data-rx-inf="uid">` 里，
  用 `firstChild.nodeValue` 就地更新，不替换节点、不触发重排。
- **事件委托**：停止滴注按钮改为在 `#rxBody` 上一次性委托绑定，列表重建后依然有效（不用每帧重新绑）。
- **动画收敛**：`.rx-item` 的入场动画移到 `.rx-item:first-child`，只有新开的那一条会滑入，
  重建时整张列表不再一起闪。

## 21. 验证（jsdom）
- 模拟主循环 20 次刷新：**DOM 节点保持同一个、新增节点数 = 0**（修复前每次都是整块重建）。
- 新开一条医嘱：只重建一次（新增 6 个节点），随后稳定。
- 停止滴注：委托按钮点击有效，`active` 置为 false，按钮在下一帧消失。
- 冒烟：六个标签来回切换、开药、停滴注、抢救成功结算，全程 0 报错。

## 27. 乱点击 / 误操作 → 可能直接心脏停搏
新增 `M.misclick(sim, act)`：4 秒窗口内反复点同一操作 ≥4 次，或 4 秒内总点击 ≥8 次，

- 拿错药 / 抽错剂量（低血压 + 心动过速，12% 室颤）

# 第十七轮：体液上限 / 胃内容量 / 放血术（v2.5.1）

## 64. 口服 / 胃内容量 10 L 上限

## 65. 修复「99999999 mL 打不死」
- 新增 `mlOf()`：任何静脉给药都折算成液体体积（ml 单位直接取、g×20、mg×1、mcg×0.001）。
- 一次给药折算 ≥ 4000 mL：提示血液稀释；**≥ 12000 mL：立刻把体液推过上限 → 容量性心脏停搏**，放血前救不回来。
- 常规剂量不受影响：500 mL 生理盐水仍然只带来约 +300 mL 体液。

## 68. 血药浓度致死模型（修复「3 L 药物血压飙高却不死」）
- **去掉毒性损伤的上限**：靶器官损伤速率改为与「毒性倍数」线性相关（只保留单帧数值稳定上限 80×，不代表临床封顶）；
  旧代码把每个器官的 ratio 截断在 30，导致浓度再高损伤也不再增加。

- **不可复苏**：停搏 ROSC、PEA 恢复、电击全部加了「毒性 < 2×」门槛；电击会提示血药浓度过高。

# 第十八轮：心电图「无端躁动 / 噪点」修复（v2.8 · v2.9）

## 69. 现象
- 监护仪 ECG 与 12 导联跑一段时间后，波形会无缘无故地抖：R 波的位置、峰高、T 波形状像被
  「揉」过，密集时整段像噪点；病情越不稳定（心率变化越快）、这一局玩得越久越明显。
- 用心律预设 / `ecgLock` 把心率钉死时基本看不到 —— 这也是它一直没被抓到的原因。

## 70. 根因
- `ecg.js` 的 `beatGrid()` 用 `R(k) = k / f` **现算**每一次心搏的时刻，而 `f` 是**当前**心率。
  心率只要变动一点点，所有心搏的时刻都会被「回头重算」：t = 100 s 时，0.3 次/分的差异就能让
  已经画过的心搏横移 0.2–0.5 s，最多接近一个完整 RR 间期。
- 引擎几乎每帧都在微调心率（实测 250 帧里 238 帧心率不同），于是波形被反复横移、重采样，
  屏幕上就是「莫名其妙的躁动 / 噪点」。t 越大、心率漂移越快，越严重。

## 71. 修法（`js/ecg.js`）
- **心搏表 `sim.ecgBeat`**：排定过的心搏时刻固定不动，新心搏按当前心率往后排；房颤的逐搏
  不规则（`hash01`）与呼吸性窦性心律不齐照旧。ECG / 动脉压 / 脉搏波 / 室速 / PEA 各自一张表，
  12 导联与监护仪仍然共用同一串心搏（同步性不变）。换心律、读档、快进（warp）时自动重建。
- **扫描式波形加跨度保护**：画布被折叠、切到别的页签或窗口卡住后回来，`span` 再长也只按
  一屏铺满，不再把几分钟硬塞进一屏像素（旧版这时会得到一整屏噪点）。
- **峰值保持的路由修正**：4 个取样点原先有 1 个（`0.17 + 0.33×3 = 1.16`）落到下一列，
  改为 0.125 / 0.375 / 0.625 / 0.875；12 导联与 10 秒节律条取样密度提到每像素 ≥ 6 点，
  R 波峰高不再每次重画都变。
- **室早不再与下一个 QRS 相撞**：RR ≤ 0.62 s（>100 次/分）时不注入室早 —— 否则 0.3 s 宽的
  室早会叠在下一个正常 QRS 上，看起来像凭空的「双 R 波」尖刺。
- 缓存号 `?v=259 → 260`（两版 `index.html`）。

## 72. 验证
- Node：同一时间窗只改心率 0.05–0.3 次/分，旧版已排定的心搏平均位移 **497 ms（最差 726 ms）**，
  新版 **0 ms**；窦性 75 时新旧波形 RMS 差 0.011 mV（只是初始相位差）。
- 监护仪缓冲对比（130 px/s、60 fps、心率 80→99 漂移）：基线相邻列跳变 >1.5 px 的比例
  从 **20.7% 降到 11.5%**（剩下的都是 P / T 波本身）。
- 各心律 10 秒取样（窦性 / 窦速 / 房颤 / 房扑 / 二度·三度 AVB / 交界性 / SVT / VT / 尖端扭转 /
  PEA / VF / 停搏 / 频发室早 / 寒战 / 低温 / 高钾）无 NaN，R 波数目正常；早期 t = 0–3 s
  （12 导联刚开始记录）也正常。
- 室早：HR 110 / 150 + arrhythmia 60 时，旧版最短 R-R 0.18–0.20 s（假「双 R」），新版 0.37–0.50 s。
- Chrome headless：急诊版监护仪连跑 120 s（心率 75→156）、诊室版 12 导联 / 前壁 STEMI 预设
  渲染正常，无 `#fatal`，0 报错。

  - 超时失控的那一刻就转入术后，不用等手术结束。
- 术后问题的「再次手术」按钮文案带上部位（如「再次手术（阑尾）」），点错也知道自己在做什么。
